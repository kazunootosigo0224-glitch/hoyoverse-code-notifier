# hoyoverse-code-notifier

原神・崩壊：スターレイルの情報をゲーム別のDiscordチャンネルへ通知するGitHub Actions用Pythonプログラムです。

## 現在の機能

- 原神・スターレイルそれぞれの専用Webhookへ通知
- 新規シリアルコードと報酬の通知
- イベント名・説明・開催期間・報酬と、取得できた公式HoYoLAB記事またはGameWithの日本語イベント案内へのリンクを通知
- キャラクター／武器／光円錐のピックアップ情報を、ゲーム別の固定ガチャ案内1件に集約して自動更新
- 固定ガチャ案内には開催中のガチャのみを表示し、開催予定の後半ガチャは開始時刻を迎えた次の定期実行で自動的に切り替え
- 各ガチャを独立したEmbedで表示し、取得元APIの★5ピックアップアイコンを対応するガチャ情報のサムネイルに表示（1メッセージ最大10ガチャ）
- スターレイルのガチャ名がAPIから省略された場合、ピックアップ対象名から「キャラクター跳躍／光円錐跳躍」の見出しを補完
- 固定ガチャ案内は初回自動作成後、Discordで手動ピン留めして運用
- カレンダーAPIが返す高難易度コンテンツの名称・分類・開催期間の通知
- 対応するイベント名・説明からの2倍報酬イベントの分類
- 開始通知、終了24時間前・3時間前のリマインド、終了通知
- 開催期間やピックアップ内容の変更検知
- 高難易度コンテンツは名称・分類・バージョン・開催期間に実質的な変更がある場合のみ更新通知し、報酬表記などの細かなAPI差分では通知しない
- カレンダーAPIが複数の高難易度コンテンツに仮ID「0」を返す場合は、名称と開催開始時刻から個別の識別子を生成し、旧履歴を引き継いで重複通知を防止
- Discord送信失敗時の再試行と、送信成功後のみ通知済み状態を更新
- 取得・解析・Discord送信などの重大エラーを集約し、GitHub Actionsを失敗として記録
- 管理者用Webhookへの障害通知（同一障害の重複通知を抑制）
- 正常実行への復帰を検知し、管理者用チャンネルへ復旧通知
- Webhook URLをログから伏せ、通知履歴ファイルの破損時は既存履歴を保護して処理を停止
- 旧形式の notified_codes.json を新しい形式へ自動移行

## Discord Webhookの設定

Discordでそれぞれ専用テキストチャンネルを作成し、各チャンネルの「連携サービス」からWebhookを作成してください。

GitHubリポジトリの Settings → Secrets and variables → Actions に、次のRepository secretsを登録します。

| Secret名 | 値 |
|---|---|
| DISCORD_WEBHOOK_GENSHIN | 原神通知チャンネルのWebhook URL |
| DISCORD_WEBHOOK_HSR | スタレ通知チャンネルのWebhook URL |
| ADMIN_ALERT_WEBHOOK | 管理者向け障害通知チャンネルのWebhook URL |

Webhook URLは認証情報として扱い、コードやIssue、チャットなどに貼らないでください。旧Secret DISCORD_WEBHOOK_URL は使用しません。ゲーム別の2つのSecretに加えて、障害通知を受け取る管理者用チャンネルのWebhookを ADMIN_ALERT_WEBHOOK に登録してください。片方のゲームWebhookが未設定の場合、そのゲームの通知は送信されず、通知済み状態も更新されないため、Secret設定後の実行時に再試行されます。管理者用Webhookが未設定の場合、障害通知を届けられないため、必ず登録してください。

## 実行方法

GitHub Actionsの HoYoverse Notifier を開き、Run workflow から手動実行できます。通常は30分ごとに自動実行します。終了前通知はActionsの実行遅延や停止の影響を受けるため、指定時刻ちょうどの通知を保証するものではありません。

通知履歴と固定ガチャ投稿のメッセージIDは notified_codes.json に保存し、Actionsが変更をコミットします。障害の通知状態は ops_state.json に保存します。通知処理に重大なエラーが発生すると、Actionsの実行を失敗として記録し、ADMIN_ALERT_WEBHOOK で指定した管理者チャンネルへ実行ログへのリンクを送信します。同じ障害が続いている間は通知を繰り返さず、正常実行に戻った際に一度だけ復旧通知を送ります。通知履歴ファイルが壊れている場合は、重複通知や固定投稿IDの消失を防ぐため、自動初期化せずに処理を停止します。初回実行で原神・スターレイルの固定ガチャ案内を各チャンネルに作成します。投稿を一度手動でピン留めしてください。以後、ガチャ情報に変更があれば同じ投稿をWebhookで編集します。Webhookが投稿を編集できなくなった場合は新しい投稿を作り直すため、再度ピン留めが必要です。既存の配列形式の履歴は新形式へ自動移行します。

## 情報源と制限事項

- シリアルコード：既存の hoyo-codes.seria.moe フィード。通知Embedから各ゲームの公式交換ページへ移動可能
- イベント／ガチャ／チャレンジカレンダー、および公式HoYoLABイベント記事：[torikushiii/hoyoverse-api](https://github.com/torikushiii/hoyoverse-api) の仕様に沿ったAPI

カレンダーAPIはイベント、キャラクター／武器バナー、チャレンジの名称・説明・開催日時などを返します。スターレイルでは武器バナーの代わりに光円錐情報が返ります。

上記は非公式の情報源です。APIの停止・仕様変更・更新遅延が発生する可能性があります。取得エラー時は空データとして既存情報を削除せず、次回の実行で再取得します。

現段階の高難易度コンテンツ通知は、カレンダーAPIが返す名称・分類・開催期間が対象です。敵編成、ウェーブ、バフ、地脈異常などの詳細データはまだ取得していません。別のゲームデータソースを接続する追加段階で実装します。

2倍イベントの分類はイベント名・説明に含まれる既知の語句を使う判定です。別の表現で掲載された場合は通常イベントとして通知される可能性があります。

## テスト

リポジトリへ変更をPush、またはPull Requestを作成すると、通知Botを実際には実行せずにユニットテストだけを自動実行します。GitHub Actionsの「Notifier Unit Tests」で結果を確認できます。

ローカルでの実行：

    pip install -r requirements.txt
    python -m unittest discover -v
    python main.py

ローカルで実際にDiscordへ送信する場合も、Webhook URLを環境変数として設定してください。URLをソースコードへ直接書かないでください。
